# AI 复核正样本客户上报

审核台的“客户上报”标签页用于把 AI 复核后的正样本按原 AI 盒子 JSON 格式上报给客户统计系统。目前只开放：

| 样本类型 | 原算法 ID | 二次处理算法 ID | 类别 ID |
| --- | ---: | ---: | ---: |
| 外卖服 | 104 | 1104 | 282624 |
| 新世界工服 | 103 | 1103 | 282368 |

## 当前自动流程

1. 同步任务把两台盒子的新图片送入审核台。
2. AI 完成复核后，只选择启用自动发送之后新采集的正样本和有效 AI 框。
3. 每分钟刷新一次原盒子事件元数据，并按设备、原算法 ID、图片文件名关联事件。
4. 每个新批次自动先发送一条金丝雀；成功后发送批次剩余项。
5. 页面“客户上报”标签页显示自动状态、最近批次和发送结果。原有手工预览/金丝雀/批量按钮保留为运维补充入口，但同样受历史截止线约束。

## 固定安全规则

- 只选择 `ai_decision=positive` 且包含有效同类 AI 标注框的样本。
- 人工复审为负样本的记录不发送。
- 只允许外卖服和新世界工服；浏览器不能修改客户地址、算法 ID 或类别 ID。
- 自动启用时按外卖服和工服分别冻结历史采集截止线；截止线以前的图片以后也永不推送。
- 同一二次处理算法 ID 下按条目 ID 和图片 SHA-256 双重去重；成功或结果不明均不自动重试。
- 不再用五分钟时间差拦截。找到同设备、同原算法 ID、同图片文件名的盒子事件即可上报；暂时找不到事件的记录留队，下一轮刷新后继续匹配。
- 每个批次先金丝雀、后批量；批量遇到首个失败或不明状态即停止。
- `ENABLE_SEND` 只在实际发送期间临时存在，操作完成或异常后立即删除。
- 发送前要求服务器至少有 1 GB 可用空间；批量结束后删除可重建的图片缓存，但保留清单、状态和 ledger。
- 审核台启动时会清理遗留启用标记；自动任务由 `ai-bot-sample-review-auto-report.timer` 每分钟触发，并带最多 5 秒随机抖动。
- 任一发送失败、结果不明、空间不足或运行异常都会让自动状态熔断暂停，后续不会自行重试。

运行证据保存在 8 服务器 `/srv/ai-bot-sample-review/report-replay/runs/<run-id>/`，包括清单、状态和逐条 ledger。文件仅限根用户读取，不包含运行凭据。

自动状态和不可变历史截止线保存在 `/srv/ai-bot-sample-review/report-replay/automatic-reporting.json`，权限为 `root:root 600`。

## OSS 图片保留

- 未经人工确认的原始/AI-only 图片从采集时间起保留 90 天。
- 人工确认的正负样本作为训练资产长期保留。
- 未人工确认样本可在 14 天后退出审核台，但 OSS 对象要到第 90 天才删除。
- 同图共享对象、未完成客户上报批次和尚未到期的保留记录均会阻止删除。
- 每日清理状态保存在 `/srv/ai-bot-sample-review/retention/last-run.json`。
